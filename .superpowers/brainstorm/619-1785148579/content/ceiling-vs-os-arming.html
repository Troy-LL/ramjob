A — Ceiling vs OS arming

Your chart stop-loss can arm RamJob when usage crosses it. SPEC also arms from OS low-memory + faults (and runaway). Pick how those rules combine. Click a card.

A

Ceiling replaces OS

Only your overall limit arms the system. OS pressure notifications ignored for Arming.

cross ceiling → ARMED
OS low-mem → ignored
runaway app → still? (open)
  • Simplest story: “I set the line”
  • Ignores real OS pressure until you tune the ceiling
  • Easy to leave Disarmed while Windows is already hurting
B · RECOMMENDED

Either can arm

Armed if OS pressure or usage crosses your ceiling. Disarm still follows recovery / your rules later.

cross ceiling → ARMED
OS pressure → ARMED
runaway → force path kept
  • GX control + real machine safety
  • Matches “stop-loss” without deleting SPEC §4.1
  • Slightly more to explain in the ⓘ copy
C

Ceiling visual only

Chart teaches the idea; Arming still only from OS (+ runaway). Crossing the line doesn’t arm by itself.

cross ceiling → warning UI only
OS pressure → ARMED
  • No SPEC change for M3
  • Your stop-loss becomes misleading if it doesn’t arm
Recommendation: B — either can arm. Keeps your stop-loss meaningful and still reacts when Windows is in trouble even if the ceiling is set high. We can refine Disarm (who wins when ceiling says “ok” but OS is still low) as a follow-up question.
